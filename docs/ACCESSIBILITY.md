# Accessibility and everyday use

Relay is a local workflow editor. Start with **Run workflow**, inspect the route, change a condition, then run again. The canvas, list view and numeric inspector edit the same graph. Dragging is optional.

## Navigation and keyboard model

- The first Tab exposes **Skip to workflow editor**. Section links lead to the workflow and run trace; **Edit selected node** opens the current inspector.
- On a node, Enter or Space opens its editor and focuses **Node name**. **Back to workflow** returns to that exact node. Pointer selection keeps focus on the canvas so a drag is not interrupted.
- Arrow keys move a focused canvas node by one pixel; Shift moves ten. Escape cancels an active pointer move. List/mobile layouts use ordinary page scrolling; **Canvas position** supplies editable X/Y fields without dragging.
- Adding through the library focuses the new node editor. Deleting a node focuses the remaining selection, or the empty inspector if none remain. Undo restores graph edits and connections; captured run evidence remains separate.
- Node descriptions expose kind, execution state, behavior and outgoing destinations, including true/false branches. Branch meaning is available without interpreting line position or color.
- Scalar and coordinate fields associate their own validation message with the input. Malformed run input focuses **Input JSON** and associates the error summary; graph-level errors focus the summary. Fixing the data and running again preserves a predictable path.

## Layout and visual states

Essential editor text and help are larger, commonly 12–13px at default zoom. Small controls have larger hit areas, coarse-pointer controls expand to 44px, and focus outlines remain visible in forced colors. At 320px the graph becomes a readable list, with the inspector beneath it. The desktop diagram has its own scrollable viewport rather than making the whole document overflow. Reduced-motion mode completes the same run without the animated delay.

## Verification

The checked-in `tests/e2e/accessibility.spec.ts` covers the initial Tab/Enter skip path, keyboard node activation and return, deletion focus, scalar/error association, run-input repair, narrow layout, enlarged text, forced colors and the numeric alternative to dragging. Existing canvas tests cover pointer capture, cancellation, touch emulation, scrolling, resizing and atomic undo. These are real browser actions with outcome assertions; focus assertions do not substitute for a screen-reader session.

Screenshots in [desktop](screenshots/desktop.png) and [mobile](screenshots/mobile.png) are regenerated by the complete browser suite. See [verification evidence](TESTING.md) for commands and scope.

## Decisions and limits

Native buttons and anchors keep ordinary browser behavior. Explicit edit/return controls avoid a modal focus trap and let people navigate between graph and inspector. Programmatic focus is requested only at a user action or validation boundary; ordinary graph updates do not steal focus. A bounded graph limits both computational cost and navigation length; no new library, network request or persistence format is needed.

This is not a WCAG conformance certification. VoiceOver/NVDA sessions, switch control, physical touch devices and user research with disabled participants have not been conducted. Automated checks cannot prove announcement timing or ease of use for every person. Browser emulation is evidence about tested rendering/interaction states only.

Guidance reviewed 23 September 2026: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [WAI page structure](https://www.w3.org/WAI/tutorials/page-structure/), [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), [Playwright accessibility testing limits](https://playwright.dev/docs/accessibility-testing).
